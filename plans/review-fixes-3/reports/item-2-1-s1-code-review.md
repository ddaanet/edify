# Review: review-fixes-3 Item 2.1/1 code review — changed-files.sh

**Scope**: `plugin/skills/build/scripts/changed-files.sh` as of HEAD (slice
commit "review-fixes-3 Item 2.1/1"): the list capture, the moved `BASE:`
print, the header comment. Tests run only, not reviewed.
**Date**: 2026-10-07
**Mode**: review + fix

## Summary

The capture-then-print order is the right shape and the slice test pins it.
The capture added a regression the Linux suite cannot see: the script no
longer parses under bash 3.2, which is macOS's `/bin/bash`, so every run that
reaches the capture dies with a syntax error. A second, smaller change was
also introduced: the output lost a trailing blank line when the last path ends
in a newline. Both are fixed. Exit 0 and exit 1 output is now byte-identical
to the pre-slice script under bash 3.2.57 and under the system bash.

**Overall Assessment**: Ready

## Method

I built GNU bash 3.2.57 locally from the ftp.gnu.org tarball, with the parser
regenerated by byacc. 3.2.57 is the version Apple ships as `/bin/bash`. The
binary is at `/tmp/claude-1000/bash32/bash-3.2.57/bash`. To run the suite
under it, `/tmp/claude-1000/bash32/bin/bash` is put first on `PATH`; the
script's `#!/usr/bin/env bash` then resolves to it. My portability claims
below come from runs of that binary, not from reading the code.

Residual bound: Apple's `/bin/bash` is 3.2.57 with Apple's own patches on top,
and this binary is upstream 3.2.57 built on Linux. The comment at line 123 is
settled as verified only by a manual run on macOS.

## Issues Found

### Critical Issues

1. **Script fails to parse under bash 3.2 (macOS)**
   - Location: `plugin/skills/build/scripts/changed-files.sh:125` (HEAD)
   - Problem: the slice moved the `case` into `paths=$(…)`. Bash 3.2 reads
     the bare pattern's `)` as the end of the substitution. Running the script
     prints `line 125: syntax error near unexpected token ';;'` and exits 2,
     with empty stdout. This happens on every exit-0 run, and on the new
     late-failure path, which therefore loses its `ERROR:` line. The
     NO-BASE path still works only because it exits before line 125.
     Evidence:
     - `bash-3.2.57 -n` on HEAD: exit 2.
     - `bash-3.2.57 -n` on HEAD~1's script: exit 0, so this is a regression.
     - Suite with 3.2 first on `PATH`: 10 failed, 6 passed. Nine of the
       failures are this syntax error.
   - Fix: open the pattern with a parenthesis,
     `("$exclude_prefix"* | plans/reports/triage-feedback-log.md)`. This is
     POSIX and accepted by every bash. A comment says why, so a later edit
     does not remove it.
   - **Status**: FIXED. `bash-3.2.57 -n`: exit 0. Suite under 3.2: 15
     passed, and the one failure is pre-existing (see Recommendations).

### Major Issues

None.

### Minor Issues

1. **Exit-0 output no longer byte-identical when the last path ends in a
   newline**
   - Location: `changed-files.sh:131–141` (HEAD)
   - Problem: `$(…)` strips every trailing newline. The previous streaming
     form printed a path `~~\n`, when it came last, as `~~\n\n`; HEAD
     printed `~~\n`. The header already accepts that such a path prints as
     two lines. The slice changed which two lines, against the requirement
     that exit 0 output stay unchanged.
   - Fix: append the sentinel `&& printf x` inside the substitution, so it is
     added only when the pipeline succeeds and a failing diff still takes the
     `||` arm. Strip it with `paths=${paths%x}`, then print with
     `printf '%s' "$paths"`. This also removes the `[[ -n $paths ]]` branch:
     an empty list prints nothing. The print comment's "The substitution
     stripped the trailing newline, and an empty list prints nothing" became
     false and was replaced by the sentinel's own comment. Nothing else was
     removed.
   - **Status**: FIXED

## Fixes Applied

- `changed-files.sh:129` — the case pattern now opens with `(`, for the bash
  3.2 parser.
- `changed-files.sh:135,139` — `done && printf x)` and `paths=${paths%x}`:
  the sentinel keeps trailing newlines in the captured list.
- `changed-files.sh:143` — `printf '%s' "$paths" || exit 2` replaces the

  kept.

  for the sentinel. The stale "substitution stripped the trailing newline"
  sentence is gone.

## Checks Requested

**Exit 0 output.** I byte-compared HEAD~1's script against the fixed script
with `cmp`, under both bash 3.2.57 and `/bin/bash`, on a scratch repo. The
repo held the paths `a b`, `tr ` (trailing space), `zz\nq`, `~~\n` (sorts
last), `p q`, a phase-corrector commit, and an empty-list state:
- empty list: `BASE: <sha>\n` only, no blank line; identical
- several paths, with spaces, with a trailing space: identical (68 bytes)
- `--phase`: identical (51 bytes)

**Exit 1.** `NO-BASE:` is identical in bytes and exit status under both
shells.

**Failure paths exit 2 with `ERROR:` alone.**
- A late diff failure goes through `pipefail` inside the substitution. That
  option is inherited by the subshell, and `set -e` is not needed there,
  because the assignment's status is tested by `||`. The slice test passes.
- The `||` sits outside the substitution, so the robustness.md
  fallback-append trap (`x=$(pipe || fb)`) does not apply. A failed pipeline
  skips `printf x`, and the list carries the pipeline's status.
- A write failure on the final prints: stdout to `/dev/full` gives exit 2
  under both shells. Each print keeps `|| exit 2`, so neither reaches
  `set -e`'s exit 1.

**Portability and whitespace.**
- The read stays NUL-delimited (`git diff -z`, `read -r -d ''`). The loop
  writes no NUL into the substitution.
- `${paths%x}`, `printf '%s'` and the `(pattern)` form are all bash
  3.2-safe, verified by the 3.2 suite run.
- shellcheck: only the pre-existing SC1091 note on the `source` line.

## Positive Observations

- Capturing the list whole, then printing, puts the ordering in the code's
  structure, so no flag or buffer discipline has to be kept.

## Recommendations

- **Lock in bash 3.2 parsing.** Nothing in the suite or `just precommit` runs
  under bash 3.2. This regression passed the Linux gate, the GREEN review and
  the test review. A cheap lock-in is a `bash -n` under a 3.2 binary, run
  where one is available. A real fix of this kind is a tests/tooling change,
  out of scope for this slice.
- **Pre-existing macOS defect, not introduced by this slice:**
  `test_unloadable_exempt_paths_is_an_error_not_no_base[absent]` fails under
  bash 3.2. With `exempt-paths.sh` missing, bash 3.2 makes the failed
  `source` on line 76 fatal and exits 1, which is `NO-BASE:`'s code, with
  empty stdout. HEAD~1's script does the same under 3.2.57 (exit 1, checked
  by hand). This macOS-target defect is worth a ticket of its own.
